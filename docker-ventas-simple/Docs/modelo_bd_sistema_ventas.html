Notas del modelo:
  • PRODUCTO_PROVEEDOR resuelve la relación muchos a muchos entre productos y proveedores (un producto puede tener varios proveedores con distinto costo).
  • PAGOS está separado de VENTAS para permitir pagos divididos o parciales por venta.
  • ESTADOS_VENTA y ESTADOS_PAGO son catálogos: evitan valores de texto inconsistentes (ej. "Pagada" vs "pagada").
  • VENTAS.total se mantiene sincronizado automáticamente por triggers cada vez que cambia un DETALLE_VENTAS.
